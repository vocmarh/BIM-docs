## 1. Проверка структуры входного файла ГПР

### 1.1 Формат и обязательные поля
- [ ] **Файл ГПР имеет корректный формат** (Excel .xlsx или .xls)
- [ ] **Присутствуют все обязательные колонки:**
  - [ ] `TOUCH_Code` (код классификатора)
  - [ ] `TaskName` (название задачи)
  - [ ] `StartDate` (плановая дата начала)
  - [ ] `FinishDate` (плановая дата завершения)
  - [ ] `SDR` (номер работы)
- [ ] **Опциональные поля присутствуют:**
  - [ ] `Duration` (длительность)
  - [ ] `Responsible` (ответственный)

### 1.2 Валидация данных
- [ ] **Все даты в корректном формате** (YYYY-MM-DD или DD.MM.YYYY)
- [ ] **StartDate ≤ FinishDate** для всех записей
- [ ] **TOUCH_Code не пустой** для всех записей
- [ ] **Отсутствуют дубли по TOUCH_Code** в рамках одного файла

---

## 2. Проверка импорта в базу данных

### 2.1 Создание версии ГПР
- [ ] **Создана запись в таблице ScheduleVersion:**
  - [ ] `VersionId` сгенерирован автоматически
  - [ ] `SourceFile` содержит имя файла
  - [ ] `VersionTag` в формате `GPR_YYYY-MM-DD_vN`
  - [ ] `ImportedAtUtc` установлена текущая дата/время
  - [ ] `ImportedBy` содержит имя пользователя
  - [ ] `IsActive = true` для новой версии

### 2.2 Загрузка данных в ScheduleBindings
- [ ] **Все строки из ГПР загружены в ScheduleBindings:**
  - [ ] Количество записей соответствует количеству строк в файле
  - [ ] `VersionId` корректно связан с созданной версией
  - [ ] Все поля (`TOUCH_Code`, `TaskName`, `StartDate`, `FinishDate`, `SDR`) заполнены
  - [ ] Опциональные поля (`Duration`, `Responsible`) загружены при наличии

### 2.3 Версионирование
- [ ] **Предыдущая версия деактивирована** (`IsActive = false`)
- [ ] **Новая версия активирована** (`IsActive = true`)
- [ ] **История версий сохранена** (можно просмотреть все импорты)

---

## 3. Проверка сопоставления с элементами Revit

### 3.1 Анализ покрытия
- [ ] **Сформирован отчёт о сопоставлении:**
  - [ ] Количество элементов с заполненным `TOUCH_Классификатор`
  - [ ] Количество найденных соответствий в ГПР
  - [ ] Количество элементов без соответствий в ГПР
  - [ ] Количество записей ГПР без соответствующих элементов

### 3.2 Заполнение плановых дат
- [ ] **Для найденных соответствий заполнены параметры:**
  - [ ] `TOUCH_Плановая_дата_начала = StartDate` из ГПР
  - [ ] `TOUCH_Плановая_дата_завершения = FinishDate` из ГПР
  - [ ] `TOUCH_ГПР_Версия = VersionTag` (опционально)
  - [ ] `TOUCH_СДР = SDR` (опционально)

### 3.3 Обработка конфликтов
- [ ] **При дублях по TOUCH_Code применено правило выбора** (например, последняя запись)
- [ ] **Элементы без TOUCH_Классификатор пропущены** без ошибок
- [ ] **Записи ГПР без соответствующих элементов** зафиксированы в отчёте

## 4. Проверка целостности данных

### 4.1 Сравнение исходных и результирующих данных
- [ ] **Даты в Revit соответствуют датам из ГПР** (выборочная проверка 5-10 элементов)
- [ ] **Названия задач корректно отображаются** в отчётах
- [ ] **СДР номера соответствуют** исходным данным

- [ ] **В модели Revit зафиксирована версия ГПР** (параметр `TOUCH_ГПР_Версия`)

- [ ] **История импортов доступна** в базе данных

### 5.1 Время выполнения
- [ ] **Импорт ГПР выполнен за разумное время** (≤ 2 минут для файла до 1000 записей)

- [ ] **Отсутствуют зависания** или ошибки памяти

### 5.2 Обработка ошибок
- [ ] **Некорректные данные обработаны корректно** (пропущены с записью в лог)
- [ ] **При ошибках импорта** система не падает, выводит понятные сообщения
