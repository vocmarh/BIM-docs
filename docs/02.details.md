# План реализации (WBS)

## Фаза 0. Каркас

- **Схема БД**  
  Используется существующая отработанная схема выгрузки Revit → MSSQL (таблицы `EL_Элементы`, `EL_EAV` и др.), применяемая на всех проектах. Дополнительного проектирования базы данных не требуется.  

- **Роли пользователей**  
  - **БИМ-отдел**  
    - отвечает за выгрузку параметров в БД;  
    - на первом этапе заполняет параметр `TOUCH_Классификатор`.  
  - **Проектировщик** (планируется в будущем)  
    - будет заполнять параметр `TOUCH_Классификатор`.  
  - **Начальник участка / ПТО**  
    - в Revit вручную заполняет `TOUCH_Фактическая_дата_начала`;  
    - в Revit вручную заполняет `TOUCH_Фактическая_дата_завершения`.  
  - **Инструмент (плагин)**  
    - автоматически заполняет `TOUCH_Плановая_дата_начала`;  
    - автоматически заполняет `TOUCH_Плановая_дата_завершения`;  
    - источником данных является ГПР и параметр `TOUCH_Классификатор`.  


## Фаза 1. Данные и модель

### Новые параметры в Revit:

- `TOUCH_Фактическая_дата_начала` — **начальник участка** (ручной ввод).  
- `TOUCH_Фактическая_дата_завершения` — **начальник участка** (ручной ввод).  
- `TOUCH_Плановая_дата_начала` — **плагин** (автоматическое заполнение на основе ГПР и классификатора).  
- `TOUCH_Плановая_дата_завершения` — **плагин** (автоматическое заполнение на основе ГПР и классификатора).  
- `TOUCH_Классификатор` — на первом этапе **БИМ-отдел**, в дальнейшем **проектировщик**.  

### Логика работы:

1. При выгрузке данных из Revit параметры сохраняются в существующую схему БД (EL_Элементы, EL_EAV).  
2. Начальник участка отвечает только за фактические даты.  
3. Плановые даты подтягиваются автоматически, исключая ручной ввод.  
4. Классификатор — ключ для сопоставления элементов с ГПР.  

## Фаза 2. Связка с ГПР (плагин + MSSQL)

**Цель:** подгружать плановые даты и данные задач из ГПР (MS Project → Excel) в базу данных с версионированием и заполнять ими параметры элементов в Revit.

### Источник данных
- Экспорт из MS Project в **Excel** (CSV/XLSX).
- Обязательные поля (в Excel могут называться иначе, важно содержание):
  - `TOUCH_Code` — код по классификатору (ключ связи с элементом Revit);
  - `TaskName` — название задачи;
  - `StartDate` / `FinishDate` — плановые даты начала и окончания;
  - `SDR` — номер работы (внутренний идентификатор задачи).
- Опциональные поля:
  - `Duration` — длительность процесса (в днях или часах);
  - `Responsible` — ответственный за процесс.

### Схема данных в MSSQL (минимум)
**ScheduleVersion** — реестр версий ГПР  
- `VersionId` (PK, авто) — идентификатор версии;  
- `SourceFile` — имя или путь к Excel;  
- `VersionTag` — например, `GPR_2025-10-05_v1`;  
- `ImportedAtUtc` — дата и время импорта;  
- `ImportedBy` — кто импортировал;  
- `IsActive` — признак активной версии.  

**ScheduleBindings** — строки ГПР для конкретной версии  
- `VersionId` (FK → ScheduleVersion);  
- `TOUCH_Code`, `TaskName`, `StartDate`, `FinishDate`, `SDR`;  
- (опц.) `Duration`, `Responsible`.  
Тип дат — `DATE` (без времени), чтобы исключить путаницу с часовыми поясами.

### Политика версий
- По умолчанию активной считается последняя импортированная версия (`MAX(VersionId)`).
- В плагине предусмотрено два режима:
  - **Auto** — использовать последнюю активную версию;
  - **Manual** — пользователь выбирает конкретную версию из списка.

### Процесс (логика)
1. Пользователь выбирает Excel-файл ГПР.  
2. Плагин парсит файл и проверяет наличие обязательных полей.  
3. Создаётся запись в `ScheduleVersion` (фиксируется файл, тег версии, дата импорта).  
4. Все строки загружаются в `ScheduleBindings`.  
5. Формируется словарь:  
   `TOUCH_Code → (StartDate, FinishDate, TaskName, SDR)`  
6. Плагин проходит по элементам модели Revit:
   - Берёт параметр `TOUCH_Классификатор`;
   - Если код найден в ГПР — записывает:
     - `TOUCH_Плановая_дата_начала = StartDate`;
     - `TOUCH_Плановая_дата_завершения = FinishDate`;
     - (опц.) `TOUCH_ГПР_Версия = VersionTag`;
     - (опц.) `TOUCH_СДР = SDR`.
7. История импортов сохраняется в БД; в модели фиксируется версия, по которой были заполнены даты.

### Валидация
- Пустые или некорректные коды — пропускаются и попадают в отчёт.  
- `StartDate > FinishDate` — строка игнорируется.  
- Дубли по одному классификатору — используется правило (например, брать последнюю по порядку).  
- Нет кода в модели — элемент пропускается.

### Роли
- **BIM-отдел** — подготавливает Excel-выгрузку и запускает импорт.  
- **Плагин** — импортирует данные, создаёт версию, сопоставляет по `TOUCH_Code`, записывает даты и метку версии.  
- **Power BI (опц.)** — использует таблицы `ScheduleVersion` и `ScheduleBindings` для отчётов и анализа версий.

### Почему так
- Централизованная история версий ГПР.  
- Простая логика в Revit — данные берутся из стабильного источника.  
- Готово к автоматизации (например, через n8n) без изменений в плагине.

## Фаза 2.1. Упрощённый вариант без БД

**Цель:** использовать ГПР из одного Excel-файла без хранения в базе данных — напрямую в плагине Revit.

### Логика процесса
1. Пользователь выбирает Excel-файл ГПР.  
2. Плагин считывает данные напрямую из файла по тем же полям:
   - «Классификатор», «Название», «Начало», «Окончание», «СДР»  
     (опц. «Длительность», «Ответственный»).  
3. Выполняется валидация и очистка данных:
   - Проверка обязательных полей;
   - Проверка дат (`StartDate ≤ FinishDate`);
   - Игнорирование пустых или ошибочных строк.  
4. Формируется словарь в памяти:  
   `TOUCH_Code → (StartDate, FinishDate, TaskName, SDR)`  
5. Плагин сопоставляет данные с моделью Revit и:
   - Подсвечивает элементы с найденными или отсутствующими кодами;
   - (опц.) Записывает `StartDate` и `FinishDate` в параметры Revit;
   - Выводит отчёт: «Найдено N элементов, не найдено M».  
6. (опц.) Экспортирует результат в CSV или Excel.

### Особенности
- Не создаёт записей в БД и не требует версионирования.  
- Подходит для быстрой проверки или разовой связки модели с ГПР.  
- Вся логика работает в памяти, результаты фиксируются только в Revit.

### Почему так
- Минимальный вход — только Excel-файл.  
- Удобно для тестов, демонстраций и пилотов.  
- Позволяет начать работу до развёртывания БД.
